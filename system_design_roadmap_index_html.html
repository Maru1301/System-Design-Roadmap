System Design 思考框架

第 1–2 週｜先學會怎麼拆問題，而不是急著畫架構圖

需求釐清與 NFR

必修

把題目拆成功能需求、非功能需求、限制條件與成功指標。

NFRSLA/SLOScope
學習重點與練習
  • 每個設計題先問：user 是誰？核心操作是什麼？讀寫比例？資料保存多久？
  • 練習：設計購物車、付款、通知系統時各列出 5 個 NFR。
  • 輸出：一頁 System Design Clarification Template。

容量估算與流量模型

必修

用粗估數字推導 QPS、storage、bandwidth、hot path 與 bottleneck。

QPSStoragePeak
學習重點與練習
  • 學會 MAU/DAU、read/write ratio、payload size、replication factor 的估算。
  • 練習：估算 100 萬會員電商平台購物車與訂單服務。
  • 輸出：Capacity Estimation Cheat Sheet。

Trade-off Thinking

核心

架構不是選最潮的技術，而是在 latency、consistency、cost、complexity 間做取捨。

LatencyCostComplexity
學習重點與練習
  • 每次選型都回答：為什麼不用另一個方案？失敗模式是什麼？
  • 練習：Redis vs DB、Queue vs Sync API、SQL vs NoSQL。
  • 輸出：ADR 範本。

API Contract Design

必修

設計穩定、可演進、可重試、可觀測的 API contract。

RESTgRPCVersioning
學習重點與練習
  • 學會 pagination、filtering、idempotency key、error code、correlation id。
  • 練習：設計 Payment Create / Confirm / Refund API。
  • 輸出：OpenAPI Spec + API Review Checklist。
2

分散式系統基本元件

第 3–4 週｜建立大型系統常見元件地圖

Load Balancer / Gateway / Ingress

必修

理解 L4/L7、reverse proxy、API gateway 與 Kubernetes Ingress 的定位差異。

L4/L7GatewayIngress
學習重點與練習
  • 比較 Azure Application Gateway、NGINX Ingress、API Gateway。
  • 練習：設計多服務入口與 auth/rate limit。

Caching Strategy

核心

掌握 cache-aside、TTL、invalidation、cache stampede 與一致性問題。

RedisTTLInvalidation
學習重點與練習
  • 何時 cache？cache key 怎麼設計？資料過期怎麼處理？
  • 練習：設計商品詳情頁、優惠券可用性、會員資料 cache。

Message Queue / Event Driven

核心

用 async processing 解耦服務、削峰填谷，並處理 retry、DLQ、順序性與重複消費。

KafkaService BusDLQ
學習重點與練習
  • 區分 command、event、message、notification。
  • 練習：付款成功後發票、通知、庫存扣減流程。
  • 輸出：Outbox Pattern 筆記。

Consistency / CAP / Saga

核心

理解強一致、最終一致、分散式交易、Saga 與補償交易。

CAPSagaOutbox
學習重點與練習
  • 什麼資料一定要強一致？什麼可以 eventual consistency？
  • 練習：設計付款、訂單、庫存跨服務一致性。
3

Backend Production Patterns

第 5–6 週｜從功能開發進化到 production-ready API

Idempotency & Retry Safety

核心

付款、下單、退款這類 API 必須能安全重試，避免重複扣款或重複建立訂單。

PaymentRetryIdempotency Key
學習重點與練習
  • 設計 idempotency key 儲存、狀態機、過期策略。
  • 練習：CreatePayment API 重送 3 次時仍只建立一筆交易。

Rate Limiting / Backpressure

必修

保護系統不被突發流量、錯誤重試、惡意請求拖垮。

Token BucketQuota429
學習重點與練習
  • 比較 fixed window、sliding window、token bucket。
  • 練習：設計 Partner API 的 per-client quota。

Database Scaling

核心

從 index、transaction isolation、read replica 到 sharding，理解資料層瓶頸。

IndexReplicaSharding
學習重點與練習
  • 練習 explain plan、hot partition、read/write split。
  • 設計：訂單表、付款表、交易紀錄表的查詢模式。

Observability

核心

用 logs、metrics、traces 找出錯誤、慢查詢、跨服務瓶頸與使用者影響範圍。

ELKApp InsightsTracing
學習重點與練習
  • 建立 correlation id、structured logging、distributed tracing。
  • 練習：付款 API timeout 的 troubleshooting flow。
4

Cloud Native / Azure / AKS

第 7–8 週｜把系統設計落到部署、擴展與維運

AKS Runtime Model

必修

理解 Pod、Deployment、Service、Ingress、HPA、Probe 如何影響可用性。

AKSHPAProbe
學習重點與練習
  • 設計 API 的 readiness/liveness/startup probe。
  • 練習：滾動部署期間如何避免流量打到未 ready 的 pod。

CI/CD 與部署策略

必修

從 build/test/push/deploy 到 blue-green、canary、rollback 與 release gate。

Azure DevOpsCanaryRollback
學習重點與練習
  • 設計 SIT/UAT/Prod pipeline 與環境設定管理。
  • 輸出：你的實務 CI/CD 架構圖。

Resilience Patterns

核心

用 timeout、retry、circuit breaker、bulkhead、fallback 控制故障擴散。

PollyCircuit BreakerTimeout
學習重點與練習
  • 避免 retry storm，區分 transient failure 與 permanent failure。
  • 練習：第三方金流 API 不穩時如何保護主系統。

Cost & Capacity Governance

進階

大型系統不只要能跑，還要能控制成本、容量與資源浪費。

CostAutoscalingLimits
學習重點與練習
  • 理解 request/limit、autoscaling、預留容量、尖峰策略。
  • 練習：促銷活動期間如何擴容又不過度浪費。
5

AI System Design

第 9–10 週｜把傳統後端能力延伸到 RAG / Agent / LLM Application

RAG Architecture

核心

理解 chunking、embedding、vector search、reranking、context assembly 與答案引用。

RAGVector DBRerank
學習重點與練習
  • 設計公司內部文件問答系統。
  • 處理文件更新、權限、引用、幻覺與評測。

Agent / Tool Calling / MCP

進階

設計能安全使用工具、存取外部系統、拆解任務與回報狀態的 Agent workflow。

AgentMCPSkills
學習重點與練習
  • 區分 prompt、skill、tool、MCP server、workflow orchestration。
  • 練習：設計可以讀 GitHub issue、產生 PR 摘要的 coding agent。

LLM Observability & Evaluation

進階

AI 系統需要追蹤 token、latency、cost、quality、prompt 版本與評測資料集。

EvalToken CostPrompt Version
學習重點與練習
  • 設計 RAG answer quality dashboard。
  • 比較人工評測、golden dataset、自動化 eval。

AI Backend Scaling

進階

處理 streaming、長任務、token quota、併發限制、模型成本與推理資源瓶頸。

StreamingQuotaInference
學習重點與練習
  • 設計 AI Chat API 的 rate limit、queue、timeout 與 cancellation。
  • 練習：多租戶 SaaS AI 功能的成本控管。
6

Design Practice & Interview Output

第 11–12 週｜把知識轉成面試與技術討論中的輸出能力

Classic Design Drills

必修

練經典題：URL Shortener、Chat、Notification、File Upload、Search、Rate Limiter。

ClassicDrillPattern
學習重點與練習
  • 每題都用同一套框架：需求 → 估算 → API → data model → architecture → bottleneck → trade-off。
  • 每題限制 45 分鐘口頭講完。

Domain Design Drills：Payment / Cart / Coupon

核心

把你的實務背景包裝成高含金量的系統設計案例。

PaymentCartCoupon
學習重點與練習
  • 整理你做過的 payment API、購物車、B2B OMO 平台經驗。
  • 輸出：一份可放履歷/面試講述的 architecture case study。

Architecture Communication

必修

學會用 C4 Model、Sequence Diagram、Deployment Diagram 與 ADR 表達設計。

C4ADRDiagram
學習重點與練習
  • 每個案例輸出 Context、Container、Sequence、Failure Handling 圖。
  • 練習：用 3 分鐘、10 分鐘、30 分鐘三種版本說明同一架構。

Portfolio & Review Loop

必修

把學習成果整理到 GitHub Pages，形成可展示的技術作品集。

PortfolioGitHub PagesReview
學習重點與練習
  • 每週完成一篇 architecture note。
  • 每兩週錄一次 10 分鐘 system design 口說。
  • 最後產出 3 個完整 case studies。

建議使用方式

  1. 每週挑 2–3 個節點。
  2. 每個節點都產出一篇 Obsidian note。
  3. 每兩週完成一題完整 system design。
  4. 最後整理成 GitHub Pages portfolio。
